# ADR-002 — Ревью ChatGPT убрано из цикла работы; инструкции разбиты на ядро и файлы по требованию

Статус: **Accepted** — решение владельца, принято и реализовано 2026-09-11.
Дата: 2026-09-11
Источник: сообщения владельца в сессии
`https://claude.ai/code/session_01TpNCsaeX9Rv7ijXATX1PLJ`:
«сейчас чат GPT больше не работает он будет брать только статистику из базы, поэтому
готовить ему отчет нет необходимости, и может както разбить большие инструкции что бы
это не сьедало столько трафика?»

## Контекст

1. Протокол `tasks/WORKFLOW.md` (введён 2026-08-29) требовал трёхстороннего цикла
   Owner → ChatGPT → Claude: Claude публиковал по каждой задаче отчёт в `tasks/reports/`,
   достаточный для независимой проверки ChatGPT, и ждал `CHANGES_REQUESTED` или разрешения.
   За 2026-08-29…09-11 так выпущено 15 отчётов.
2. `CLAUDE.md` обоих репозиториев отправляются в модель на каждом ходу каждой сессии:
   15,1 КБ в `llicena` + 13,7 КБ в `licena-docs` = 28,8 КБ постоянного контекста,
   большая часть которого не относится к текущей задаче (правила авторства банков при
   правке CSS, стандарт practice-страниц при правке документации).

## Решение

1. **ChatGPT выведен из цикла ревью.** Цикл: Owner → Claude → Owner. Отчёт под ревью
   по каждой задаче не готовится; вместо него — сводка владельцу в чате и строка
   в `26_CHANGELOG.md`. ChatGPT читает базу знаний как источник статистики, поэтому
   документы `01`–`29` остаются главным продуктом репозитория и должны быть точными.
2. **Инструкции разбиты на постоянное ядро и файлы по требованию.** Содержание правил
   не менялось — разделы перенесены дословно:
   - `llicena/CLAUDE.md` 15,1 КБ → 6,4 КБ; вынесено в `docs/rules/`:
     `agent-lanes.md`, `banks.md` (форма банков + авторство вопросов), `practice-pages.md`.
   - `licena-docs/CLAUDE.md` 13,7 КБ → 6,8 КБ; вынесено в `audit/`:
     `FILES.md` (состав базы знаний), `DOC-STANDARD.md` (стандарт документа и правила аудита).
   В каждом ядре — таблица маршрутизации «работаешь с X → прочитай Y» и список
   инвариантов, которые должны быть в контексте всегда.

## Последствия

- Постоянный контекст сессии: 28,8 КБ → 13,2 КБ (−54 %).
- Риск: правило, вынесенное в файл по требованию, будет пропущено, если сессия не
  прочитает файл перед работой в его области. Смягчение: таблица маршрутизации в ядре
  и явная пометка «ОБЯЗАТЕЛЬНО прочитать перед…» в шапке каждого вынесенного файла;
  опасные инварианты (деплой = push в `main`, платные банки не в `main`, `opts` не
  переупорядочивать, не переименовывать DOM-хуки, `verify.js` после правки банков,
  один источник цены) продублированы в ядре.
- Архив `tasks/reports/` и `tasks/reviews/` сохраняется; предыдущий протокол — в
  git-истории `tasks/WORKFLOW.md`.
- Не затронуто: правило правдивости данных, append-only журналов, запрет секретов
  в публичном репозитории, запрет мержа и деплоя без разрешения владельца.
