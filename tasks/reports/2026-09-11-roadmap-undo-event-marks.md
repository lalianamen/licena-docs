# LICENA License Roadmap V3 — исправление отмены ручных отметок выполнения — отчёт для владельца

Последняя сверка: 2026-09-11
Статус: **READY_FOR_REVIEW**. Merge в `main` и production deploy НЕ выполнялись — только после отдельного подтверждения.

## 1. Причина ошибки и описание исправления

**Причина.** `setStatus(key, status)` при выборе «Выполнено» на пяти карточках-событиях записывал факт в `answers`
(`issued = "y"`, `appSubmitted = "a_yes"`, `appStatus = "st_accepted"`, `fingerStatus = "fp_done"`, незакрытые экзамены → `x_pass`),
а при обратном изменении статуса меняла только `steps[key].status` с флагом `manual`. Факт оставался, `derive()` продолжал
выводить из него остальные статусы, рекомендация и блок «готов к работе» исходили из выдачи лицензии.
Воспроизведено на `3cb2136` Playwright-скриптом: после «Лицензия выдана» → «Не начато» `answers.issued` = `"y"`, карточка
«Финальная цель», рекомендация «Finish your ready-to-work checklist», блок RTW показан, после перезагрузки «10 из 11 этапов».

**Исправление** (минимальное, на существующей модели данных; коммит `4c5d1d5`):

| Требование спецификации | Что сделано |
|---|---|
| §1 Прогресс ≠ событие | Пять карточек-событий выделены в `RML.EVENT_STEPS` (`submit_application`, `application_review`, `fingerprinting`, `schedule_pass_exams`, `license_issued`). Остальные шаги (классификация, опыт, подготовка заявления, подготовка к экзаменам, финальные требования) меняют статус как раньше, без диалогов. |
| §2 Уточнение при отмене | Для карточки-события переход из «Выполнено» в любой менее завершённый статус открывает внутри карточки подтверждение «Исправить отметку о выдаче лицензии?» (свой вопрос на каждое событие) с кнопками «Да, исправить сведения» / «Отмена — оставить как есть». После подтверждения открывается существующая анкета на нужном блоке (`appstat` — подача / статус / экзамены / выдача, `finger` — отпечатки) с сохранёнными ответами; фактическое состояние выбирается из существующих вариантов («Подано — жду ответа», «Принято», «Не знаю текущий статус», для экзаменов — по каждому экзамену отдельно). В анкете, открытой из плана, добавлена ссылка «← Вернуться к плану без сохранения». |
| §3 Согласованное обновление | До подтверждения ничего не сохраняется: выпадающий список возвращается к «Выполнено», `answers` не тронуты. После «Показать мой план» `finishWizard` пересобирает статусы из ответов (`derive`), пересчитывает следующий шаг, «Вы здесь», сводку, прогресс, предупреждения и зависимые этапы. Для карточек-событий ручной флаг после анкеты не переносится — ответы становятся единственным источником. |
| §4 Без автоматического сброса | Для экзаменов анкета спрашивает каждый применимый экзамен отдельно (`examBlock`): сданный остаётся `x_pass`, подтверждённое освобождение `x_waived` не теряется, для назначенного запрашивается дата. Отмена принятия не отменяет подачу (`appSubmitted` остаётся `a_yes`). Отмена выдачи не трогает экзамены и финальные требования. Отпечатки «Пройдены → Назначены»: дата встречи запрашивается (исправлен побочный дефект — прежний флаг `saved.finger` сворачивал блок без запроса даты), прежняя дата прохождения сохраняется, но статус карточки не определяет. |
| §5 Происхождение сведений | Отметка события через карточку теперь синхронизирует и стадию анкеты (`appStage` = `stg_issued` / `stg_acc` / `stg_waiting`), чтобы исправление начиналось с того, что показывала карточка. Подпись «Статус отмечен вами. LICENA ничего не проверяет в CSLB» осталась. |
| §6 Без потери данных | Ответы, переставшие применяться (номер лицензии, даты, финальные требования при возврате экзамена в «назначен»), не удаляются, а откладываются в `answers.aside` (`stash()` в `prune()` и в ветке «не подано»); ничто их не читает, к текущему состоянию они не применяются. |
| §7 Старые конфликтующие записи | При каждом показе плана `RML.eventConflicts(steps, answers)` находит карточки-события с ручной отметкой, противоречащей ответам (в обе стороны). Вместо рекомендации показывается «Разрешите противоречие: {шаг}» с кнопками «Да, лицензия выдана» (существующая подпись `mc_*`) / «Нет — этого ещё не произошло». Пока не разрешено: спорный факт маскируется при выводе статусов и сводки (`maskContested`), блок «готов к работе» не показывается, прогресс из спорного факта не считается; сами ответы не меняются. После ответа данные согласованы, повторных диалогов нет (проверено перезагрузкой). |

Побочно исправлено: возобновлённый черновик анкеты (после перезагрузки посреди правки) теперь знает свой план — доступна
ссылка назад, и завершение анкеты обновляет тот же сохранённый план, а не создаёт новый. Ссылка «назад без сохранения»
очищает черновик.

## 5. Недоступные проверки и оставшиеся ограничения

- typecheck / lint в проекте отсутствуют (vanilla JS без сборки).
- Путь с реальной сессией Supabase не прогонялся (нет тестового аккаунта); сохранение проверено фальшивым клиентом (`db-roundtrip`). Схема не менялась: `aside` живёт внутри `answers` (jsonb), флаг `manual` — в `license_roadmap_steps.metadata`.
- Ручная отметка «Выполнено» на карточке-событии по-прежнему пишет факт и держит флаг `manual` (например, «отпечатки пройдены» до подачи заявления остаётся «выполнено» на карточке, хотя модель не выводит этот статус без подачи); при последующем прохождении анкеты ответы побеждают.
- `answers.aside` накапливает отложенные значения и нигде не отображается — только хранится.
- Уточнение идёт через существующую анкету, а не через отдельный мини-диалог: пользователь видит блок анкеты целиком (стадия, экзамены, номер заявления). Это осознанный выбор ради одной модели данных.
