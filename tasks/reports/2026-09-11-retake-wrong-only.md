## 2. Что сделано

### 2.1. Поведение
- На карточке результата блока (`#resultsCard`) появилась кнопка `#retakeWrongBtn` —
  «Retake wrong only (N)» / «Repetir solo los errores (N)» / «Пересдать только ошибки (N)», где N —
  число ошибочных ответов в активном блоке. Показывается только при N > 0; при 100 % — скрыта.
  Стиль `btn-gold` (акцентная CTA дизайн-системы, как «Finish & submit» в Final Exam); «Try again»
  остаётся `btn-primary`. Обе кнопки — в новом ряду `.result-actions` (flex, перенос на 360 px).
- Клик → `retakeWrong()`: из `lp:answers:<course>` удаляются ТОЛЬКО ошибочные ответы активного блока
  (`scopeWrongIds()`), правильные сохраняются; варианты стёртых вопросов перемешиваются заново
  (`clearOptPerms`); `activeSection = null`; включается существующий фильтр `filterWrong`; порядок
  перетасовывается (`resetOrder(true)`). Прогон идёт только по ещё не решённым вопросам блока:
  «Question 1 of N», прогресс «0 / N». Подтверждение не запрашивается (стираются только ошибки).
- Запись `lp:runs` (прошлый прогон блока для сравнения) при пересдаче НЕ создаётся: это запись
  о полном прогоне. Сравнение «Last run» на карточке результата теперь показывается только при
  `prev.total === total` — иначе результат подмножества (пересдача, секция) сравнивался бы с полным
  прогоном и давал бессмысленную дельту.
- Пересдачу можно повторять: после прогона по 10 вопросам с 3 ошибками карточка результата
  предлагает «Retake wrong only (3)»; когда ошибок нет — кнопка скрыта.

### 2.2. Что НЕ менялось
- «Try again» / «Restart» (`resetBlockRun`) — по-прежнему сброс всего блока с подтверждением и
  архивацией прогона.
- Сайдбарный фильтр «Wrong only» — по-прежнему только просмотр (варианты отвеченных вопросов
  заблокированы). Во время пересдачи он включён и показывает «✓ Wrong only (M)», где M — текущее
  число ошибочных ответов по всему курсу (после стирания ошибок блока это может быть 0) — семантика
  метки не менялась, см. §8.
- Final Exam (таймер, набор вопросов, результат, review) — не затронут: пересдача только ошибок
  противоречила бы «условиям экзамена».
- Схема Supabase, RLS, Edge Functions, платежи, аналитика, маршруты — не тронуты. Новых событий
  аналитики нет (в `js/app-course.js` вызовов `track()` нет и не было).
- Ключи localStorage (`lp:answers`, `lp:optperm`, `lp:order`, `lp:runs`, `lp:summary`) — те же;
  сводка для кабинета (`updateCourseSummary`) обновляется через `saveAnswers()` как при любом ответе.

## 8. Нерешённые вопросы (для владельца)

1. Метка сайдбарного фильтра «✓ Wrong only (M)» во время пересдачи показывает число ошибок по всему
   курсу (после стирания ошибок блока — часто «(0)»), хотя прогон идёт по N вопросам. Семантика метки
   существующая, не менялась; можно показывать число вопросов в текущем прогоне — отдельное решение.
2. Ярлык результата пересдачи («✓ Passed!» при ≥ 70 % от подмножества) считается по прогону, как и для
   секций сегодня; отдельного ярлыка «пересдача» нет.
3. Перезагрузка страницы посреди пересдачи: фильтр «Wrong only» не сохраняется (существующее поведение) —
   плеер откроет полный порядок блока на первом неотвеченном вопросе; стёртые ответы при этом не теряются.
4. Метка `from-chat` на issue #189 и ответ пользователю через тикет — за владельцем.

## 9. Дополнение 2026-09-11 (позже): кнопка пересдачи доступна в любой момент, отдельно для каждого блока

Замечание владельца по превью `08ef240`: если после прохождения блока не нажать пересдачу сразу, потом её не
найти. Ошибочные ответы при этом сохранялись (localStorage), но кнопка жила только на карточке результата,
которая появляется после последнего вопроса прогона; при возврате в курс блок открывается на первом вопросе,
и до карточки нужно долистать весь блок. Указание владельца: «сделай кнопку доступной», «отдельно для каждого
блока». Второй коммит в той же ветке — `75e901f` (полный `75e901f1ffd8d94b7eeac1710a0e71d010b616e2`), поверх
`08ef240`; `main` не изменён, не задеплоено.

Сделано:
- В сайдбаре (`.side-controls`, между «Wrong only» и «Restart») новая кнопка `#retakeWrongSideBtn`
  «Retake wrong only (N)» с иконкой, той же строкой `courseRetakeWrong` EN/ES/RU и тем же `retakeWrong()`.
  N и действие — по АКТИВНОМУ блоку: переключение карточки блока меняет счётчик; при N = 0 кнопка отключена
  (`updateRetakeWrongBtn`, вызывается из `updateFilterWrongBtn`, т. е. при каждом ответе, смене блока/секции,
  пересдаче и смене языка). Ответы других блоков пересдача не трогает. После клика из сайдбара карточка вопроса
  подводится под липкую шапку (`scrollToCardTop`) — на телефонах сайдбар лежит ниже карточки.
- Единственное касание существующего кода: `wrongCount()` (метка фильтра «Wrong only (N)») теперь считает
  ошибки активного блока, а не всего курса. Сам фильтр и раньше сужал порядок только текущего блока, так что
  метка «14» при 10 отфильтрованных вопросах была неточной; рядом с новой кнопкой два разных числа читались
  как противоречие (см. скриншот до правки в истории сессии: «Wrong only (14)» / «Retake wrong only (10)»).

- CSS `.ctrl-btn-retake` (`:disabled` как у фильтра; на телефонах — на всю ширину ряда, как фильтр).
  Бампы: `js/app-course.js` v71, `css/course.css` v37 (`course.html`, `preview.html`). Строки не менялись.
