# LICENA — протокол работы Owner → Claude

Последняя сверка: 2026-09-11

## Изменение протокола 2026-09-11

Ревью ChatGPT из цикла УБРАНО по решению владельца. ChatGPT больше не проверяет задачи
и не выставляет `CHANGES_REQUESTED`; он читает базу знаний как источник статистики.
Отсюда два следствия:

1. **Отчёт под ревью для каждой задачи больше не готовится.** Вместо файла в
   `tasks/reports/` — короткая сводка владельцу в чате и строка в `26_CHANGELOG.md`.
2. Цикл стал двухсторонним: Owner → Claude → Owner.

Предыдущий протокол (Owner → ChatGPT → Claude, трёхсторонний, с обязательным отчётом
под независимую проверку) действовал с 2026-08-29 и лежит в git-истории этого файла.
Папки `tasks/reports/` и `tasks/reviews/` сохраняются как архив — не удалять.

## Роли

**Owner** — ставит задачу, принимает результат, единственный, кто разрешает мерж
в `main` и деплой.

**Claude** — выполняет задачу в отдельной ветке; проверяет результат; показывает
владельцу короткую сводку и, для UI, превью и скриншоты; обновляет документацию;
ждёт решения владельца.

## Цикл

1. Владелец ставит задачу (в чате или карточкой в `tasks/`).
2. Claude работает в назначенной ветке. Мерж и деплой — не выполняет.
3. Claude запускает проверки, предусмотренные для области правки
   (`node scripts/verify.js`, рендер desktop + 360px, EN + RU, ноль ошибок консоли;
   для UI — превью на точном коммите).
4. Claude показывает владельцу сводку: что сделано, ветка и коммит, что проверено,
   что НЕ проверено и почему, открытые вопросы. Честно называет непроверенное.
5. Владелец решает: доработать, разрешить мерж или остановить задачу.
6. Только после явного разрешения — мерж в `main`; деплой Edge Functions и применение
   миграций всегда за владельцем.
7. После мержа Claude проверяет выкладку и обновляет `26_CHANGELOG.md` и профильные
   документы.

## Статусы задач в `tasks/`

| Статус | Значение |
|---|---|
| `READY_FOR_CLAUDE` | владелец поставил задачу; Claude может начать |
| `IN_PROGRESS` | Claude выполняет |
| `READY_FOR_REVIEW` | работа готова, ждёт решения владельца |
| `APPROVED_FOR_MAIN` | владелец разрешил мерж (ставит только владелец) |
| `DONE` | мерж и деплой выполнены, выкладка проверена |
| `DO_NOT_MERGE` | мерж запрещён |

## Что остаётся обязательным

- Ветка на задачу; никакого мержа и деплоя без разрешения владельца.
- Проверки перед сводкой; непроверенное называется явно, не замалчивается.
- Никаких выдуманных данных: неизвестное — `UNKNOWN`.
- Публичный репозиторий: без секретов и персональных данных пользователей.
- `26_CHANGELOG.md` и `decisions/` — append-only.
