# CLAUDE.md — постоянная инструкция по проекту LICENA

Ядро правил. Всё, что нужно не в каждой задаче, вынесено в файлы по требованию
(таблица в конце) — решение владельца 2026-09-11 об экономии контекста.

## 1. Роль

- Роль Claude двойная: **разработка LICENA** (сайт licena.us, репозиторий
  `lalianamen/llicena`) и **поддержание фактической документации** проекта.
- Репозиторий `lalianamen/licena-docs` — единая база знаний проекта и единственное
  место хранения документации.
- **ChatGPT больше НЕ ревьюит задачи** (решение владельца 2026-09-11). Он читает базу
  знаний как источник статистики о проекте. Поэтому: отчёт под ревью для каждой задачи
  больше не готовится; документы `01`–`29` остаются главным продуктом этого репозитория
  и должны быть точными.
- Бизнес-аудит и оценки Claude не проводит: документы содержат факты, без выводов
  и рекомендаций.
- При работе с кодом действует `CLAUDE.md` основного репозитория. При противоречии
  приоритет у настоящего файла.

## 2. Правдивость данных — главное правило

- **Запрещено придумывать отсутствующие данные.** Ни домыслов, ни экстраполяций,
  ни «примерных» цифр, ни правдоподобных заполнителей.
- Каждый факт прослеживается до первоисточника: файла в основном репозитории
  (код, SQL, `docs/**`, git-история) или явного сообщения владельца. Факты берутся
  из текущего состояния репозитория, а не по памяти.
- **Если информации нет или её нельзя проверить — писать ровно `UNKNOWN`**
  (при необходимости с уточнением: `UNKNOWN — в репозитории нет данных о …`).
- Пустые шаблоны запрещены: документ либо содержит реальные данные (с `UNKNOWN`
  на местах пробелов), либо не создаётся вовсе.

## 3. Синхронизация кода и документации

- **После каждого значимого изменения кода** — в том же рабочем цикле обновить
  затронутые документы. Значимое: новая функциональность; изменение схемы БД, API,
  Edge Functions, платежей, безопасности, зависимостей, структуры контента,
  SEO-механики, деплой-процесса; выпуск банка/курса.
- Обязательно обновлять: `26_CHANGELOG.md`, `28_AI_CONTEXT.md` и профильные документы
  по теме изменения.
- **Историю удалять запрещено.** `26_CHANGELOG.md`, `decisions/` и прочие журналы —
  только пополняются (append-only). Ошибочная запись помечается отменённой новой
  записью, но не стирается. Force-push и переписывание git-истории запрещены.
- Крупные архитектурные изменения оформляются как ADR в `decisions/` до реализации.

## 4. Публичность и безопасность

licena-docs — **публичный** репозиторий. Запрещено помещать в него секреты: API-ключи,
токены, пароли, содержимое `.env`, персональные данные пользователей. Вместо значения
указывается место хранения («секрет задан в Supabase Edge Function secrets») либо `UNKNOWN`.

## 5. Рабочий процесс

- Язык документации — русский; имена файлов, технические термины, идентификаторы
  и цитаты кода — на английском. Маркер отсутствия данных — всегда `UNKNOWN`.
- Работать в ветке, назначенной для текущей сессии; коммиты — с ясными описательными
  сообщениями; push — после завершения логического блока работы.
- Мерж в `main` основного репозитория — только с явного разрешения владельца.
- В каждом документе указывать дату последней сверки (`Последняя сверка: YYYY-MM-DD`).

## 6. Экономия контекста (решение владельца 2026-09-11)

Этот файл отправляется в модель на КАЖДОМ ходу сессии, вместе со всей историей.
Поэтому: читать файл правил только когда работаешь в его области; не загружать большие
справочники ради одного факта; проверять минимально достаточным прогоном; длинную новую
задачу начинать новой сессией.
