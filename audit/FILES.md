# Структура базы знаний — состав файлов

Вынесено из CLAUDE.md 2026-09-11 (экономия контекста). Читать, когда создаёшь или
переименовываешь документ базы знаний. Содержание не менялось.

## 4. Структура базы знаний (файлы аудита)

Создать и поддерживать файлы аудита с `01_PROJECT_OVERVIEW.md` по
`29_BUSINESS_FRAMEWORK.md` плюс `30_CTO_REPORT.md`. Имена 01, 29 и 30 заданы
владельцем; канонические имена 02–28 закреплены настоящим файлом:

| Файл | Содержание |
|---|---|
| `01_PROJECT_OVERVIEW.md` | Что такое LICENA: продукт, домен, статус, аудитория, языки |
| `02_ARCHITECTURE.md` | Общая архитектура (static frontend + Supabase), ключевые потоки |
| `03_REPO_STRUCTURE.md` | Структура основного репозитория, назначение каталогов и файлов |
| `04_DATABASE.md` | Схема Postgres: таблицы, RLS, функции БД, миграции |
| `05_API.md` | Интерфейсы: Supabase RPC, обращения клиента, контракты данных |
| `06_FUNCTIONS.md` | Edge Functions: назначение, входы/выходы, имена секретов |
| `07_AUTH_ACCESS.md` | Аутентификация, entitlements, анти-шеринг устройств |
| `08_SECURITY.md` | Модель безопасности и задокументированные слабые места |
| `09_PAYMENTS.md` | Stripe: продукты, цены, trial, вебхуки, статусы подписок |
| `10_CONTENT_MODEL.md` | Банки вопросов: форматы, инварианты, paid/free, ветка `content-banks-src` |
| `11_I18N.md` | Языки и локализация интерфейса и контента |
| `12_SEO.md` | SEO-механика: `js/seo.js`, sitemap, robots, страницы practice/guides |
| `13_UX.md` | Страницы и пользовательские потоки (auth → кабинет → плеер) |
| `14_ANALYTICS.md` | Аналитика и сбор событий (pageview, stats, GSC) |
| `15_METRICS.md` | Реальные числа: объёмы банков, KPI, данные GSC — только факты |
| `16_PERFORMANCE.md` | Производительность: кэширование PWA/SW, размеры, узкие места |
| `17_TECH_DEBT.md` | Технический долг — только реально существующий в коде |
| `18_DEPENDENCIES.md` | Зависимости: vendor-библиотеки, внешние сервисы, версии |
| `19_INFRASTRUCTURE.md` | Хостинг, домены, деплой, GitHub Actions |
| `20_VERIFICATION.md` | Проверки качества: `scripts/verify.js`, чекеры, ручные чек-листы |
| `21_AGENT_PROCESS.md` | Агентные «дорожки» (lanes) и правила совместной работы |
| `22_MARKETING_STATE.md` | Фактическое состояние маркетинга (планы, спеки) — без оценок |
| `23_SMM_STATE.md` | Фактическое состояние SMM: каналы, паки, календарь, очередь |
| `24_RISKS.md` | Реестр рисков — только задокументированные факты |
| `25_DECISIONS.md` | Журнал решений (ADR): дата, решение, контекст, источник |
| `26_CHANGELOG.md` | История изменений проекта |
| `27_ROADMAP.md` | Дорожная карта — из реальных планов владельца и репозитория |
| `28_AI_CONTEXT.md` | Сводный контекст для AI-сессий: текущее состояние, где что лежит |
| `29_BUSINESS_FRAMEWORK.md` | Фактические бизнес-данные: модель, цены, условия — без оценок |
| `30_CTO_REPORT.md` | **Создаётся ПУСТЫМ.** Заполняет ChatGPT — Claude его не редактирует |

Вне нумерации:

- `RELEASE_SUMMARY.md` — сводка по релизам, в корне репозитория;
- `rfc/` — папка RFC/ADR (крупные изменения до реализации);
- `README.md` — оглавление базы знаний;
- `audit/INDEX.md` — реестр всех документов: статус заполнения, дата последней
  проверки, уровень достоверности;
- `audit/COVERAGE.md` — карта покрытия: какие части основного проекта уже
  задокументированы, какие нет.
  Оба файла обновляются при каждом изменении состава или статуса документов.
