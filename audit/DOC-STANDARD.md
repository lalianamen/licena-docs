# Стандарт документа базы знаний

Вынесено из CLAUDE.md 2026-09-11 (экономия контекста). Читать ПЕРЕД тем, как писать или
править любой документ `01`–`29`. Содержание не менялось.

## 5. Что обязательно фиксировать

Документация обязана покрывать: архитектуру, базу данных, API, функции,
безопасность, производительность, технический долг, зависимости, решения,
риски, SEO, UX, аналитику, метрики и историю изменений.


## 9. Стандарт документа для независимого аудита (действует с 2026-08-05)

Документация читается не только разработчиками, но и независимым аудитором
(ChatGPT). Каждый документ базы знаний обязан соответствовать правилам:

1. Только **проверяемые факты**.
2. **Каждое утверждение** имеет ссылку на источник внутри проекта: файл,
   директорию, миграцию, модуль, ветку или коммит основного репозитория.
3. Отсутствующая информация — ровно `UNKNOWN`.
4. Никаких выводов, оценок и предложений улучшений.
5. Никаких общих фраз — только конкретные сведения (имена, числа, пути, даты).
6. Обязательный раздел **«Source References»**: полный список файлов проекта,
   из которых получена информация документа.
7. Обязательный раздел **«Verification Status»** с одним из уровней:
   - **Verified** — каждое утверждение проверено чтением названного источника;
   - **Partially Verified** — часть данных помечена `UNKNOWN` и/или взята из
     описаний (комментариев, документов), не перепроверенных по реализации —
     такие места названы явно;
   - **Unknown** — документ не проходил проверку.
8. Если сведение выводится из нескольких файлов — перечисляются **все**.
9. `audit/INDEX.md` (реестр документов) и `audit/COVERAGE.md` (карта покрытия)
   обновляются при каждом создании или изменении документа.
