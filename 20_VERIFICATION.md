## Автоматические проверки (запускаются вручную/агентами)

`node scripts/verify.js` — один прогон четырёх проверок (файл прочитан
полностью; exit 1 при любой ошибке):

| Чекер | Что проверяет |
|---|---|
| `check-banks.js` (полностью прочитан) | **Ошибки**: файл банка не исполняется; дубль `id`; пустой стем/опция; не 4 опции; дубль опций в вопросе; `correct` вне диапазона; нет `sec`; смесь block/blockless; `block` вне формы; дословный дубль стема. **Переводы** (ошибки): дубль id; id вне EN-банка; число опций ≠ EN; пустые. **Предупреждения**: нет `re`; length cue (ключ >1.6× среднего); all/none of the above; отклонение от формы банка (N×M ±10%); near-dup стемы (Жаккар ≥0.75); перекос ключей по буквам (>40 %/<10 % при ≥40 вопросах); `correct` в оверлее; неполное покрытие перевода; отсутствие ru/es-оверлея |
| `check-paid-sync.js` (полностью) | идентичность course-id-списков платных банков в 5 файлах / 7 местах: PAID_COURSES, PAID_SUBS, PAID map, allowlist `start_trial`, оба RLS not-in списка. Рассинхрон = ERROR. Введён после инцидента 2026-08-04 (шапка файла) |
| `check-course-ref.js` (шапка) | у каждого exam-курса запущенных категорий есть справочная панель COURSE_REF; guides и незапущенные вертикали исключены. Введён после пропусков c33/az-sre |
| `node --check` | синтаксис всех не-vendor JS (`js/**` рекурсивно + корневые `*.js`) |

Правило запуска: обязательно после любой правки `js/questions/*`
(`CLAUDE.md` осн. репо); на `content-banks-src` чекер запускается там же
(процесс платных банков, `10_CONTENT_MODEL.md`).

## Ручной чек-лист (обязательный, `CLAUDE.md` осн. репо, раздел 4)

- Рендер страницы Playwright-скриншотом и осмотр: desktop **и** 360px, EN
  **и** длинно-строчный язык (RU).
- Fail при любой ошибке браузер-консоли; клик по одному потоку (ответ → Next
  → Back, переключение блока) — «идеальный скриншот может скрыть мёртвый
  обработчик». Вопрос искать по `id` (порядок перемешан).
- Grep-симметрия хуков: после правки HTML/CSS — каждый `id`/`class`/`data-*`,
  который читает JS, существует; после правки JS — обратное.
- Каждый новый CSS-класс определён; каждый inline `<svg>` имеет явный размер
  (инцидент: «An unsized icon once shipped oversized to prod; only rendering
  caught it»).
- «Reading the diff is not verification — render it».

## CI

Автоматического запуска проверок НЕТ: ни один из 4 workflow не запускает
`verify.js`/тесты на push или PR (все 4 файла прочитаны — триггеры issues /
pull_request closed / push путей `docs/smm/queue*`). Workflow
`claude-support.yml` инструктирует Claude в промпте выполнять `node --check`
и grep хуков в рамках работы над тикетом — это агентная, не пайплайновая
проверка.

## Области БЕЗ автоматических проверок (факт отсутствия)

- Рендеринг UI: скриншоты/клики — только ручные (нет e2e в CI).
- HTML/CSS: валидность и целостность хуков — только grep-чек-лист вручную.
- `js/seo.js` и структурированные данные — никакой валидации.
- Edge Functions: тестов нет вовсе (в `supabase/functions/*` — только
  `index.ts`).
- SQL: миграции/политики не проверяются автоматически.
- Переводы: чекер ловит структуру (id/число опций/`correct`), но не
  содержание; семантические повторы вопросов — только ledger + ревью.
- `sw.js`, `manifest.json`, workflows — без проверок.
- Производительность и доступность — не проверяются (`16_PERFORMANCE.md`).
- Внешние ссылки — только ежемесячная ручная проверка агентом resources.
